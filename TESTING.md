# Сценарий тестирования для отчёта

Документ для того, кто проводит замеры: человека или агента. Результат — файлы в `results/` и разметка в `evals/data/`, из которых заполняются разделы 4–10 `REPORT.md`. Код менять не нужно; если что-то не работает, запишите это в «Журнал отклонений» в конце файла и сообщите.

**Стенд:** Ryzen 5 7500F, Radeon RX 7700 XT 12 ГБ, 32 ГБ DDR5, Windows 11 + WSL2 (Ubuntu). Ollama работает в Windows на GPU, всё остальное — в WSL2 на CPU.

## Чек-лист

- [ ] 1. Windows: драйвер AMD, Ollama, модель `qwen3.5:9b`
- [ ] 2. WSL2: FFmpeg, uv, репозиторий, зависимости
- [ ] 3. Проверки окружения пройдены
- [ ] 4. Данные: кадры сцены размечены (≥ 200, ≥ 30 на класс)
- [ ] 5. Данные: кадры с рамками (≥ 100) и клипы с подсчётами (≥ 10)
- [ ] 6. Данные: фрагменты без речи (≥ 20)
- [ ] 7. Прогоны: текст, аудио, изображение, видео
- [ ] 8. Прогон LLM и ручная оценка ответов
- [ ] 9. Сводная таблица и передача результатов

## 1. Windows: Ollama на GPU

1. Установите актуальный драйвер AMD Software: Adrenalin Edition. Ollama требует драйвер с поддержкой ROCm v7 / HIP ([docs.ollama.com/gpu](https://docs.ollama.com/gpu)); RX 7700 XT есть в списке поддерживаемых.
2. Установите Ollama для Windows с [ollama.com/download](https://ollama.com/download).
3. Разрешите подключения из WSL2. Выберите **один** вариант:
   - **Зеркальная сеть WSL (проще).** В `%UserProfile%\.wslconfig` добавьте:
     ```ini
     [wsl2]
     networkingMode=mirrored
     ```
     Затем выполните `wsl --shutdown` в PowerShell. Из WSL Ollama будет доступна по `http://localhost:11434`.
   - **Адрес хоста.** Задайте системную переменную Windows `OLLAMA_HOST=0.0.0.0:11434`, перезапустите Ollama и разрешите порт 11434 в брандмауэре для частной сети. Из WSL используйте адрес Windows: `ip route show default | awk '{print $3}'`.
4. В PowerShell:
   ```powershell
   ollama pull qwen3.5:9b
   ollama run qwen3.5:9b "Скажи привет одним словом"
   ollama ps
   ```
   В `ollama ps` в колонке `PROCESSOR` должно быть **`100% GPU`**. Если там `CPU` или смешанное значение, запишите это в журнал: замеры LLM без GPU в отчёт не идут.
5. Запишите версию: `ollama --version`.

## 2. WSL2: окружение

```bash
sudo apt update && sudo apt install -y ffmpeg git curl
curl -LsSf https://astral.sh/uv/install.sh | sh && source ~/.bashrc
git clone <репозиторий> llm-lab && cd llm-lab
uv sync --locked --group eval
```

Переменные окружения на время замеров (добавьте в `~/.bashrc`):

```bash
export OLLAMA_BASE_URL=http://localhost:11434   # или http://<адрес Windows>:11434
export OLLAMA_SEED=42
export HF_TOKEN=<токен Hugging Face, необязательно: ускоряет скачивание>
```

Работайте внутри файловой системы WSL (`~/llm-lab`), а не в `/mnt/c/…`: там чтение файлов в разы медленнее, и это исказит латентность.

## 3. Проверки окружения

```bash
make check                                   # линтер и юнит-тесты, должно быть «passed»
curl -s $OLLAMA_BASE_URL/api/tags | head -c 300   # должен быть JSON со списком моделей
ffmpeg -version | head -1
lsb_release -d && uv run --locked python -V
```

Запишите версии Ubuntu и Python в журнал (пойдут в раздел 3.1 отчёта).

## 4. Данные: кадры для классификации сцены (задача 3)

**Нужно:** ≥ 200 размеченных кадров, ≥ 30 на каждый из 5 классов, с ≥ 8 разных каналов.

1. Выберите каналы разных жанров: шутеры, стратегии, гонки, Just Chatting. Классы «загрузка», «меню» и «заставка» встречаются редко, поэтому:
   - снимайте каналы в начале трансляции (часто идёт заставка «скоро начнём»);
   - для меню и загрузки подойдут записи (VOD), скачанные локально: `--video путь`.
2. Снимайте кадры с интервалом 15 с, по 40 кадров с канала:
   ```bash
   uv run --locked python -m scripts.collect_stream_data frames --channel <канал> --every 15 --count 40 \
       --out evals/local/scene/frames --manifest evals/data/scene_labels.csv
   ```
   Для локального видео замените `--channel <канал>` на `--video <файл>`.
3. Откройте `evals/data/scene_labels.csv` и заполните колонку `label` одним из значений: `gameplay`, `menu`, `loading`, `streamer_camera`, `intermission`. Правила — `REPORT.md`, Приложение Г. Неоднозначный кадр оставьте с пустой меткой: он не попадёт в оценку.
4. Проверьте баланс:
   ```bash
   cut -d, -f2 evals/data/scene_labels.csv | sort | uniq -c
   ```
   Если в каком-то классе меньше 30 кадров, доснимите. Запишите в журнал число кадров с пустой меткой.

## 5. Данные: детекция и трекинг (задача 4)

### 5.1 Кадры с рамками

**Нужно:** ≥ 100 кадров с ≥ 5 каналов, где есть объекты классов COCO (чаще всего `person`; также `car`, `sports ball`, `chair`, `cup` и т.п.).

1. Снимите кадры в отдельную папку:
   ```bash
   uv run --locked python -m scripts.collect_stream_data frames --channel <канал> --every 20 --count 25 \
       --out evals/local/video/det/images
   ```
2. Разметьте рамки в [CVAT](https://www.cvat.ai/) или Label Studio. Названия меток пишите как в COCO (`person`, `car`, `sports ball`…); полный список классов — `uv run --locked python -c "from ultralytics import YOLO; print(list(YOLO('yolo26s.pt').names.values()))"`. Правила разметки — Приложение Г.
3. Экспортируйте в формате **YOLO 1.1** (CVAT) или **YOLO** (Label Studio). Положите `.txt` в `evals/local/video/det/labels/` (имена как у картинок), а файл списка классов (`obj.names` или `classes.txt`) — в `evals/local/video/det/`. Скрипт сам сопоставит номера классов с COCO по названиям.
4. Кадр без объектов тоже допустим: для него нужен пустой `.txt`.

### 5.2 Клипы для трекинга

**Нужно:** ≥ 10 клипов по 30 с, в которых можно уверенно сосчитать разные объекты одного класса (люди в IRL-трансляциях и спорте, машины в гонках).

1. Запишите клипы:
   ```bash
   uv run --locked python -m scripts.collect_stream_data clip --channel <канал> --seconds 30 \
       --out evals/local/video/clips
   ```
2. Просмотрите каждый клип и посчитайте, сколько **разных** объектов выбранного класса появлялось за весь клип. Объект, который вышел из кадра и вернулся, считается один раз.
3. Создайте `evals/data/video_clips.csv`:
   ```csv
   path,class,true_count
   ../local/video/clips/<имя>.mp4,person,3
   ```
   Пути указываются относительно папки `evals/data/`.

## 6. Данные: фрагменты без речи (задача 2)

**Нужно:** ≥ 20 фрагментов по 3–5 с: музыка, звуки игры, тишина, без голоса.

Вырежьте их из записанных клипов: найдите на слух место без речи и выполните

```bash
uv run --locked python -m scripts.collect_stream_data noise --video evals/local/video/clips/<клип>.mp4 \
    --start <секунда> --seconds 4 --out evals/local/audio/noise
```

Прослушайте каждый файл. Если слышна речь, удалите его.

## 7. Прогоны: задачи 1–4

Перед каждым прогоном закройте браузер с трансляцией и другие тяжёлые программы. Время — грубая оценка для этого CPU.

| Задача | Команда | Примерно |
| --- | --- | --- |
| Текст | `make eval-text` | 5 мин |
| Аудио | `make eval-audio EVAL_ARGS="--limit 300 --noise-dir evals/local/audio/noise"` | 1–2 ч (две модели; первый раз скачивается 565 МБ FLEURS и ~2 ГБ весов) |
| Изображение | `make eval-image` | 5 мин |
| Видео | `make eval-video` | 15–30 мин |

После каждого прогона в консоли печатается главная метрика и путь к файлу в `results/`. Если прогон аудио слишком долгий, сначала запустите `--limit 50`, чтобы оценить скорость, и запишите это в журнал.

## 8. Прогон LLM и ручная оценка

1. Убедитесь, что Ollama запущена и `ollama ps` после пробного запроса показывает `100% GPU`.
2. Запустите:
   ```bash
   make eval-llm
   ```
   Скрипт задаст 30 вопросов (первый включает загрузку модели) и сохранит `results/llm/<дата>_<commit>.json` и рядом `…review.csv`.
3. Сразу после прогона выполните в PowerShell `ollama ps` и сохраните вывод в журнал.
4. Откройте `review.csv` (LibreOffice / Excel, кодировка UTF-8) и для **каждой** строки заполните 4 колонки:

   | Колонка | Значения |
   | --- | --- |
   | `score_correct` | 0 — неверно, 1 — частично, 2 — верно |
   | `score_grounded` | 0 — опирается на выдумку, 1 — частично, 2 — только на контекст |
   | `score_style` | 0 — не по-русски или не по формату, 1 — с недочётами, 2 — по-русски, 2–4 предложения |
   | `hallucination` | 1 — есть утверждение, которого нет в контексте; иначе 0 |

   Контекст каждого сценария — в `evals/data/llm_scenarios.json` (по `id`). Колонка `auto_flags` подсказывает, где автоматическая проверка нашла проблему, но решение за вами. Для ловушек (`trap=True`) правильный ответ — «данных нет»; любой конкретный ответ — `hallucination=1`.
5. Сохраните файл в CSV (UTF-8, разделитель запятая) и выполните:
   ```bash
   make eval-llm-review REVIEW=results/llm/<файл>.review.csv
   ```
   В результат добавится раздел `manual` со средними баллами.

## 9. Сводная таблица и передача результатов

```bash
make summary-table
```

Передайте обратно (коммитом в ветку или архивом):

- [ ] папку `results/` целиком (JSON и заполненный `review.csv`);
- [ ] `evals/data/scene_labels.csv` и `evals/data/video_clips.csv`;

## Если что-то не работает

| Симптом | Что сделать |
| --- | --- |
| `curl $OLLAMA_BASE_URL/api/tags` не отвечает | Проверьте шаг 1.3: зеркальная сеть WSL или `OLLAMA_HOST=0.0.0.0` и брандмауэр |
| `ollama ps` показывает CPU | Обновите драйвер AMD; проверьте, что модель помещается в 12 ГБ (не запущены другие модели: `ollama stop <модель>`) |
| Ошибка 429 / медленное скачивание с Hugging Face | Задайте `HF_TOKEN` |
| `Channel … is offline` | Канал не в эфире — выберите другой |
| `ffmpeg: not found` | `sudo apt install -y ffmpeg` |
| Нехватка памяти при аудио | Запустите модели по одной: `EVAL_ARGS="--models openai/whisper-small --limit 300"`, затем `--models openai/whisper-large-v3-turbo` |
| `Classes not in the model's COCO list` | Переименуйте метки в CVAT точно как в COCO и экспортируйте заново |
